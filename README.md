# Multi-Agent Warehouse Coordination System

## Requirements

- Java JDK 21
- JADE 4.6.0
- IntelliJ IDEA or another Java-compatible IDE

The project uses `jade.jar` as an external dependency.  
After installing JADE 4.6.0, add `jade.jar` to the project libraries/classpath from the JADE `lib` directory.

## Running the project

1. Open the project in IntelliJ IDEA.
2. Configure JDK 21 as the project SDK.
3. Add JADE 4.6.0 `jade.jar` as a project library.
4. Create an Application run configuration with:
    - Main class: `jade.Boot`
    - Program arguments:

```text
-gui coordinator:smwarehouse2.CoordinatorAgent;robot1:smwarehouse2.RobotAgent;robot2:smwarehouse2.RobotAgent;robot3:smwarehouse2.RobotAgent
```

5. Run the configuration.

The `-gui` option starts the JADE Remote Agent Management GUI (RMA), where the coordinator and robot agents can be inspected during execution.

A Java-based multi-agent simulation developed with the JADE framework to model the coordination of autonomous robot agents in a warehouse environment.

The system uses a central coordinator agent and multiple robot agents to manage zone coverage, detect and resolve simulated incidents, exchange ACL messages, and evaluate the simulation through a quantitative scoring model.


## Architecture

The system follows a centralized multi-agent architecture composed of:

- **Coordinator Agent**: manages the global state of the simulation, assigns warehouse zones, receives incident notifications, tracks resolutions, and calculates the final score.
- **Robot Agents**: operate in assigned zones, perform patrol activities, report incidents, react to scenario conditions, and communicate with the coordinator.
- **Warehouse Zones**: represent the simulated areas that must remain covered by the robot agents.
- **Incident Model**: represents detected events, including the affected zone, reporting robot, and resolution state.
- **Scoring System**: evaluates coverage, incident detection, resolution, unattended zones, unresolved incidents, and late responses.

Agent communication is implemented through JADE ACL messages.

## Project evolution

The project was developed incrementally in two main versions:

- **Version 1 (`smwarehouse`)** introduced the basic multi-agent structure with one coordinator agent and three robot agents. It implemented robot registration, fixed zone assignment, patrol behavior, ACL communication, and a simple simulated incident flow.
- **Version 2 (`smwarehouse2`)** extended the initial system with explicit robot states, configurable simulation scenarios, incident tracking, zone coverage management, a scoring model, and quantitative simulation results.

The second version is the main implementation of the project and is the one used for the validated execution documented in this repository.

## Simulation scenarios

Version 2 defines four simulation scenarios:

- **BASE**: normal operation without simulated incidents or coverage failures.
- **SINGLE_INCIDENT**: one robot reports an incident that must be processed and resolved.
- **MULTI_INCIDENT**: multiple incidents can be generated by different robot agents.
- **COVERAGE_FAILURE**: simulates the loss of availability of a robot, affecting warehouse zone coverage.

The current validated configuration uses **`SINGLE_INCIDENT`** as the primary scenario because it provides a stable end-to-end execution of incident detection, coordinator response, resolution, and final evaluation.

## Robot states

Version 2 models the operational state of each robot explicitly through the following states:

- **`IDLE`**: the robot is available but not currently performing an active task.
- **`PATROLLING`**: the robot is monitoring its assigned warehouse zone.
- **`RESPONDING_INCIDENT`**: the robot is handling a detected incident.
- **`SUPPORTING`**: the robot is providing support during coordinated operations.
- **`UNAVAILABLE`**: the robot is temporarily unable to cover its assigned zone.

These states make the behavior of each agent easier to track during the simulation and allow scenario-specific changes in robot availability and activity.

## Scoring system

The simulation includes a quantitative scoring model to evaluate system performance:

- **+10 points** for each covered warehouse zone.
- **+20 points** for each detected incident.
- **+15 points** for each resolved incident.
- **-10 points** for each unattended zone.
- **-15 points** for each unresolved incident.
- **-5 points** for a late response.

The scoring mechanism provides a simple quantitative summary of coverage quality and incident-management performance at the end of each simulation.

## Agent communication flow

The agents coordinate their actions through JADE ACL messages.

A typical incident-management flow is:

1. The coordinator initializes the simulation and assigns warehouse zones to the robot agents.
2. Each robot begins operating in its assigned zone.
3. When an incident is detected, the corresponding robot notifies the coordinator.
4. The coordinator registers the incident and processes the received information.
5. The robot performs the simulated response and reports the resolution.
6. The coordinator updates the global simulation state and the scoring model.
7. At the end of the simulation, the coordinator prints the final result.

This message-based interaction keeps agent responsibilities separated while allowing the coordinator to maintain a global view of the simulated warehouse.
